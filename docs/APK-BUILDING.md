# Building the Routstr Chat APK with pakstr

This branch adds everything needed to package the web app (`out/` static Next.js
export) as a signed, installable Android APK using
[pakstr](https://git.nostrdev.com/stuff/pakstr) — and to upload it to a Blossom
server for public download.

The APK itself is **not** committed (`*.apk` is gitignored); it is produced from
`out/` by the build pipeline.

## What's in this branch

| File | Purpose |
|---|---|
| `pakstr.yaml` | pakstr config: appId, version, icon/splash, permissions, upload target |
| `zapstore.yaml` | Zap Store publisher whitelist (only needed for full store publishing) |
| `scripts/upload-blossom.mjs` | Spec-correct BUD-02 Blossom uploader (works with strict servers) |
| `scripts/docker-podman-shim.sh` | `docker` → `podman` compat shim for podman-only machines |

## Key config decisions (`pakstr.yaml`)

- **`appId: com.routstr.chat`** — the appId is an input to the signing-key
  derivation and cannot be changed after the first release without breaking
  update continuity. `pakstr init` suggested `dev.pakstr.routstr_chat`; we chose
  `com.routstr.chat` before anything was published.
- **`build.web: ./out`** — the Next.js static export (`pnpm build` with the
  `static` script flow produces `out/index.html`).
- **Icon/splash** — `public/icons/icon-512.png` (also used for the splash), dark
  `#333333` background matching the app theme.
- **Permissions** — `INTERNET`, `NOTIFICATIONS`, `VIBRATE` (no camera).
- **Publishing** — upload enabled (Blossom), `zapstore.enabled: false` until a
  full store release is intended.

## The signing secret (`PAKSTR_NSEC`)

- Generated by `pakstr init` into **`.env`** (gitignored, never committed).
- The APK signing key is derived deterministically from `nsec + appId`, so the
  **same nsec must be reused for every future release** — a different nsec
  produces a different signing key and updates won't install over prior APKs.
- Back this nsec up somewhere safe. Anyone who has it can sign updates for the
  app; losing it means existing installs can never be updated.

## How the first APK was built (record)

Our local Mac has no Docker, so the build ran on `<build-server>` (podman 5.8.4,
Node 24) over SSH:

1. **Docker shim on <build-server>** (pakstr shells out to `docker`):
   ```sh
   scp scripts/docker-podman-shim.sh <build-server>:~/bin/docker
   ssh <build-server> 'chmod +x ~/bin/docker'
   ```
   The shim execs podman and strips `uid=0,gid=0` from pakstr's `--tmpfs`
   mounts (podman rejects them; they're no-ops anyway).
2. **Sync config + secrets + web assets**:
   ```sh
   rsync -av pakstr.yaml zapstore.yaml .env <build-server>:~/projects/routstr_main/routstr-chat/
   rsync -a --delete out/ <build-server>:~/projects/routstr_main/routstr-chat/out/
   ```
   (Remote `out/` differed from local; local is the source of truth.)
3. **Build + sign**:
   ```sh
   ssh <build-server> 'cd ~/projects/routstr_main/routstr-chat && pnpm dlx pakstr run'
   # — or, to skip a rebuild when an unsigned APK already exists:
   ssh <build-server> 'cd ~/projects/routstr_main/routstr-chat && pnpm dlx pakstr sign'
   ```
   First run pulls the pakstr builder image (multi-GB) and runs the Gradle
   build (~4–5 min); signing derives the key in-memory (tmpfs) — nothing
   secret touches disk. Output: `build/com.routstr.chat.apk`.
4. **Copy back**: `scp <build-server>:…/build/com.routstr.chat.apk build/`

## Uploading to Blossom

`pakstr publish` (BUD-02 `PUT /upload` with a kind-24242 auth event) failed on
several servers:

- `cdn.zapstore.dev` → **403**: only accepts uploads tied to a registered
  Zap Store publisher (requires the full kind-32267 app registration flow)
- `blossom.band` → **415**: APK file type not allowed on the free tier
- `cdn.satellite.earth` → **502**: server down
- `blossom.primal.net` → **400**: pakstr encodes the auth event as
  base64**url**; strict BUD-02 servers expect plain base64

The bundled `scripts/upload-blossom.mjs` does BUD-02 by the book (plain base64
auth event, `exp`/`t`/`x` tags, correct APK content type) and works:

```sh
node scripts/upload-blossom.mjs build/com.routstr.chat.apk https://blossom.primal.net
```

Public download URL is `https://blossom.primal.net/<sha256>` (primal's response
`url` field doubles the hash path — use the single-hash canonical endpoint).

## Releasing a new version

1. Bump `version` in `package.json`, and `versionName`/`versionCode` in
   `pakstr.yaml` (versionCode must be monotonic).
2. `pnpm build` → fresh `out/`.
3. `pakstr run` (or build+sign on <build-server> per above) with the same `.env` nsec.
4. Upload with `scripts/upload-blossom.mjs` and/or proceed to Zap Store.

## Full Zap Store publishing (not yet done)

To appear in Zap Store you need kind-32267 app metadata + NIP-82 release events
on `wss://relay.zapstore.dev`. The relay authorizes the publisher by fetching
`zapstore.yaml` from the `repository` URL over **HTTPS** — the ngit remote
(`nostr://…`) doesn't satisfy that, so the repo would need an HTTP(S) mirror
(GitHub/Gitea) or a Gitea-release upload config. Use a long-lived release nsec
(CI secret manager) rather than the local dev one at that point.
